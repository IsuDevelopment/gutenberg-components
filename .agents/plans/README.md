# Plans

Implementation plans, one file per feature: `YYYY-MM-DD-<feature-name>.md`.

A plan turns an approved spec from `../specs/` into ordered, bite-sized, independently
testable tasks with the exact files, code and commands for each. It is written to be
executed by someone — or something — with no prior context on this project.

Plans live here, not under `docs/`, for the same reason specs do: they are shared working
context, not published documentation.

Executed plans are kept, not deleted. `../status.md` is the live view of progress; a plan
is the historical record of how a feature was built, and its task list is the fastest way
to reconstruct why the code looks the way it does.
